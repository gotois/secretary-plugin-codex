# Task decomposition

Превращай цель в короткий проверяемый план. Secretary MCP используй
только для чтения сохранённого контекста и для уже подтверждённых
пользователем действий.

## Workflow

1. Определи исходную задачу из запроса. Если речь о сохранённой задаче и
   её данных нет в контексте, прочитай подходящий период через
   `list-calendar-tasks`; не выдумывай поля задачи.
2. Сформулируй один измеримый результат и критерий готовности. Задай один
   короткий вопрос, только если без ответа нельзя выбрать правильную
   границу декомпозиции.
3. Предложи 2–7 подзадач в логическом порядке. Каждая должна:

   - описывать одно наблюдаемое действие;
   - иметь понятный результат;
   - содержать оценку активного времени;
   - явно называть зависимость, если она есть.

4. Не дроби задачу на микрошаги и не добавляй этапы, не влияющие на результат.
   Сохрани дедлайны и ограничения исходной задачи; не назначай даты без
   запроса на планирование.
5. Покажи план до любых изменений в Secretary. Дождись edit, confirm или reject.
6. После явного подтверждения передавай каждую подзадачу в `$task-intake`: он
   выберет одну из четырёх категорий, проверит время и подготовит
   `prepare-create-form`. Не вызывай `create` напрямую.

## Guardrails

- Не создавай подзадачи до подтверждения всей декомпозиции.
- Не утверждай, что подзадачи сохранены, пока UI не подтвердил создание.
- Не выдумывай ownership, parent ID, status, category или другие поля Secretary.
